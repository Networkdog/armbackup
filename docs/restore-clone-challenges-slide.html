Azure Control Plane · Restore & Clone Constraints Standard Load Balancer & Application Gateway (WAF_v2)

왜 복원·복제는 단순 ARM JSON 재전송(Raw PUT)으로 구현할 수 없는가?

백업된 원본 JSON에는 이질적인 종속 수명주기, 전역·서브넷 고유 식별자, NIC 소유 백엔드 역참조, 생성 후 불변·상태 의존 속성이 혼재되어 그대로 전송하면 즉시 거부되거나 운영 장애를 유발한다.

Load Balancer (L4) Application Gateway (L7 · WAF_v2)
✕ 단순 ARM GET → PUT 재전송 시: 1:1 참조 충돌 · 중복 IP/DNS 거부 · 불변 필드 오류 · 운영 NIC 간섭 발생
구조도 LB · App Gateway 종속 지형
inline 내장 contained 귀속 exclusive 1:1 shareable 공유 shared-infra 망 excluded 제외
01

연관·종속 리소스 수명주기 불일치

종속성 · 순서
  • 노출 계층 차이: RG 상단의 Public IP(1:1)·WAF(N:1)와 부모 내부 전용인 Backend Pool은 수집·복제 단위가 다름
  • 배열 덮어쓰기: ARM PUT이 하위 배열 전체를 교체해 신규 서브넷·사용 중 풀의 암묵 삭제(InUse) 유발
  • 위상 순서 강제: 선행 리소스 Succeeded 확인 → 부모 생성 → 하위 풀 PUT 순서가 어긋나면 즉시 실패
02

복원·복제 시 다층 고유값 충돌

식별자 · 주소
  • 리전 유일 DNS: 공용 IP domainNameLabel은 리전 전체에서 유일해야 하며 reverseFqdn은 소유권 검증으로 실패
  • 서브넷 IP 충돌: 동일 서브넷 공유 복제 시 사설 프런트엔드 정적 IP(privateIPAddress)가 원본과 즉시 충돌
  • AGW v2 비대칭 제약: Internal LB는 Dynamic 전환이 되지만, AGW v2는 Static 필수라 미사용 새 IP 지정이 강제됨
03

Backend Pool NIC 중복·역참조 제약

NIC · 중복 거부
  • 역참조 소유권: backendIPConfigurations는 LB가 아닌 NIC 리소스 속성이라 LB PUT으로 NIC를 추가할 수 없음
  • 동종 LB 중복 거부: 동일 NIC IP 구성(및 사설 IP)은 원본과 복제본 같은 유형의 두 LB 풀에 중복 등록될 수 없음
  • 무중단 우회 생성: 운영 NIC를 분리할 수 없으므로 복제 풀은 임시 사설 IP(placeholder) 또는 빈 풀로 생성해야 함
04

불변(Immutable) 속성 및 상태 제약

불변 · 런타임
  • 서버 전용·계열 불변: etag·할당 ipAddress(M0)는 제거 필수이며, AGW v1↔v2 불일치(M1)는 제자리 복원 불가
  • 생성 후 불변(M2): location, zones, LB sku, PIP ipTags, AGW enableFips 충돌 시 현재 값 보존(keep-current) 필요
  • 상태 부작용(M3): 연결된 PIP는 SKU·할당 변경이 잠기며, Stopped AGW에 PUT 전송 시 의도치 않게 자동 Running 기동
