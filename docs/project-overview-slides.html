01 / 05 배경과 목적 · 왜 만들었나

복잡한 네트워크 설정, 장애 시 처음부터 다시 만들 수 있는가?

서버·DB 데이터 백업만으로는 수십 개 규칙과 참조가 얽힌 제어 평면(Control Plane) 형상을 되살릴 수 없다.

해결

핵심 가치 3가지
핵심 목적 빈 리소스 생성이 아니라, 다시 세팅하기 까다로운 운영 네트워크 형상과 연결을 안전하게 재현한다.

02 / 05 제품 컨셉 · 무엇을 다루고 무엇을 덜어냈는가

서버 이미지 백업이 아닌 "검증된 형상 금고 + 의미 인식 재현기"

모든 리소스를 얕게 복제하는 범용 도구 대신, 재구성 비용이 큰 핵심 네트워크 묶음을 끝까지 책임진다.

Configuration Vault
비대상 · 데이터 평면 (Data Plane)
VM OS·디스크 · DB 데이터 · 실시간 트래픽 · 비밀 원문
집중 범위 · 제어 평면 형상 (Control Plane)
라우팅·리스너·프로브·WAF 정책·백엔드 풀 및 연관 참조
대상 선정

고비용 복합 리소스 집중

주 리소스 선택 시 복구에 필수인 동반 리소스를 같은 스냅샷으로 자동 수집

수집·보관

탐색과 정본 수집 분리

비동기 색인(ARG)에 의존하지 않고 실제 Provider 응답과 무결성 해시를 보관

웹 콘솔 UI

탐색·비교·실행 일체화

달력 시점 탐색 → 속성 Diff 대조 → 계획 승인·실행까지 한 화면에서 수행

핵심 컨셉 탐색(ARG) · 수집(REST) · 검증(SHA-256) · 재현(Configuration Vault 콘솔)을 단일 환경에 통합했다.

04 / 05 구현 난제 · 왜 복원과 복제가 가장 어려운가

백업한 원본 JSON을 그대로 PUT하면 왜 실패하는가?

Load Balancer와 Application Gateway에는 4가지 Azure 제어 평면 제약이 동시에 얽혀 있다.

Configuration Vault
01

연관·종속 수명주기와 배열 덮어쓰기

순서 · InUse

RG 노출 여부와 생성 순서가 모두 다르며, 단순 덮어쓰기 시 운영 연결이 끊어짐

02

복제 시 고유 식별자·주소 충돌

Unique 제약

Application Gateway v2는 동적 사설 IP를 지원하지 않아 새 정적 IP 재할당이 필수

03

Backend Pool의 NIC 중복 등록 불가

NIC 소유권

풀 멤버는 NIC 소유 읽기 전용 역참조이며, 운영 NIC를 떼지 않고 복제 풀에 중복 연결 불가

04

불변 속성 및 런타임 상태 전이 함정

불변 · 상태

불변 속성 충돌 시 업데이트가 거부되며, 중지된 게이트웨이는 PUT 즉시 과금·트래픽이 재개됨

핵심 난제 복원·복제는 단순 파일 복사가 아니라 리소스 관계·식별자·상태를 재해석하는 컴파일 과정에 가깝다.
